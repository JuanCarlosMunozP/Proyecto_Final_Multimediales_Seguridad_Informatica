# ADR-002: Máquina de estados finitos

**Estado:** Propuesto
**Fecha:** 2026-11-06
**Prioridad:** Alta
**Relacionado:** ARQ-001, FSM-001, FSM-002, FSM-003

## Contexto

main.js gestiona los estados:
- cargando
- inicio
- jugando
- pausa
- cinematica
- victoria
- derrota

Las asignaciones están distribuidas entre
funciones de entrada, diálogo, finalización
y el bucle principal.

## Decisión propuesta

Extraer progresivamente la gestión de
estados a un módulo JavaScript independiente.

La FSM deberá:
1. Mantener un estado válido.
2. Recibir eventos explícitos.
3. Rechazar transiciones no autorizadas.
4. Conservar el contexto de cinemáticas.
5. Permitir pruebas sin navegador.
6. Evitar dependencias directas de Three.js.
7. Separar transiciones de efectos secundarios.

## Alternativas

A. Conservar asignaciones directas.
B. Introducir una biblioteca FSM externa.
C. Implementar una FSM pequeña y propia.

## Alternativa preferida

C. FSM propia, sujeta a validación de pruebas.

## Estrategia de migración

1. Documentar comportamiento actual.
2. Crear pruebas de caracterización.
3. Implementar FSM independiente.
4. Integrar una transición por vez.
5. Ejecutar pruebas de regresión.
6. Validar gameplay manualmente.

## Riesgos

- Alterar reanudación de cinemáticas.
- Modificar el comportamiento de pausa.
- Cambiar el orden de efectos secundarios.
- Introducir regresiones en el gameplay.

## Criterios de aceptación

- Transiciones válidas documentadas.
- Transiciones inválidas rechazadas.
- Estados terminales controlados.
- Reanudación de cinemáticas conservada.
- Build de producción exitoso.
- Pruebas unitarias e integración ejecutadas.

## Estado de aprobación

Pendiente de revisión humana.
