# ADR-001: Refactorización incremental

**Estado:** Propuesto
**Fecha:** 2026-11-06

## Contexto

El videojuego funciona con Three.js,
Vite y módulos JavaScript.

main.js coordina numerosos componentes.
Una reescritura completa introduciría
riesgos de regresión y nuevos costes.

## Decisión propuesta

Mantener el stack tecnológico actual.

Separar responsabilidades mediante
refactorizaciones pequeñas y verificables.

Introducir pruebas automatizadas antes
de modificar lógica crítica.

## Alternativas consideradas

1. Reescribir completamente el videojuego.
2. Migrar a otro framework.
3. Refactorizar incrementalmente.

## Justificación

La tercera alternativa permite conservar
funcionalidades y controlar los riesgos.

## Consecuencias positivas

- Menor riesgo de regresión.
- Reutilización del código existente.
- Cambios revisables.
- Mejor trazabilidad.

## Riesgos

- Convivencia temporal de código antiguo
  y componentes refactorizados.
- Necesidad de pruebas de regresión.
- Mayor esfuerzo inicial de documentación.

## Criterios para aceptar la decisión

- El build continúa funcionando.
- El gameplay existente se conserva.
- Las nuevas dependencias están justificadas.
- Las pruebas permiten detectar regresiones.

## Aprobación

Pendiente de revisión humana.
